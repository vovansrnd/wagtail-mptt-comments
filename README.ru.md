# wagtail-mptt-comments

**Предоставляет древовидные комментарии к страницам, антиспам для гостей, модерацию, уведомления и инструменты Wagtail Admin. Плагин предназначен для комментариев под статьями, а не для форумных разделов и личных сообщений.**

## Основные возможности

- Вложенные ответы на базе django-mptt.
- Honeypot, временной токен и простая проверка для гостевых отправок.
- Необязательная модерация и уведомления администраторам/авторам ответов.
- Теги шаблонов для дерева комментариев и виджета новых комментариев с фильтрацией по текущему Site.

## Требования и совместимость

- Заявленные зависимости: `Wagtail >= 6.0; django-mptt >= 0.16.0; django-prose-editor >= 0.26; nh3 >= 0.2.14`.
- Совместимость Python, Django и Wagtail нужно проверять совместно. Нижняя граница зависимости пакета не является подтверждением поддержки каждой версии.

В метаданных пакета заявлен Wagtail >= 6.0, однако нижняя граница зависимости не доказывает совместимость со всеми версиями. В архиве нет полной автоматизированной матрицы Django/Wagtail. Перед обновлением production проверьте точные версии, базу данных, файловое хранилище и настройки развёртывания на тестовом стенде.

## Установка

Установите пакет в то же виртуальное окружение, где работает ваш проект Wagtail:

```bash
pip install wagtail-mptt-comments
```

Добавьте приложения в указанном порядке, сохранив остальные приложения и зависимости проекта:

```python
INSTALLED_APPS = [
    # Сохраните и остальные зависимости Django/Wagtail, требуемые проекту.
    "mptt",
    "django_prose_editor",
    "wagtail_mptt_comments",
]
```

```python
from django.urls import include, path
urlpatterns = [
    # ...
    path("comments/", include("wagtail_mptt_comments.urls")),
]
```

Выполните `python manage.py migrate wagtail_mptt_comments`.


## Первоначальная настройка

Минимальный пример для начала работы. Замените имена моделей, поля API и URL на соответствующие вашей конфигурации.

```django
{% load mptt_comment_tags %}
{% render_comments page %}
```

Последние комментарии можно вывести через `{% get_latest_comments 5 as latest_comments %}`. Используйте тег в контексте запроса, где определён текущий Wagtail Site.

Используйте тег вместо повторной подготовки дерева, формы и счётчика в `Page.get_context()`. Полная таблица настроек, порядок модерации и CSS-переменные приведены в английском README.

### Важные замечания

В шаблоне используйте `{% render_comments page %}` и не готовьте форму/дерево повторно в `get_context()`. Виджет последних комментариев должен быть ограничен текущим Wagtail Site; доверие к proxy-заголовкам оставляйте выключенным без настроенного доверенного прокси.

## Безопасность и эксплуатация

- Поддерживайте зависимости в актуальном состоянии. Для пользовательского HTML используйте предусмотренную очистку и вывод; не применяйте безусловный `|safe` к сохранённым комментариям или сообщениям форума.
- Проверьте миграции и разрешения под обычной учётной записью, пользователем с ограниченными правами, модератором и администратором.

## Обратный прокси и ограничение частоты комментариев

По умолчанию плагин использует `REMOTE_ADDR` и **не доверяет** `X-Forwarded-For`. Это безопасное поведение, пока провайдер не подтвердил схему проксирования.

Если поддержка хостинга сообщила точные IP/CIDR прокси и подтвердила, что прокси удаляет клиентский `X-Forwarded-For` или корректно дописывает собственную цепочку, задайте:

```python
COMMENTS_TRUST_PROXY_HEADERS = True
COMMENTS_TRUSTED_PROXY_IPS = ("10.0.0.10/32",)  # заменить на подтверждённый адрес/сеть
```

Не используйте `0.0.0.0/0` или `::/0`. Не включайте доверие к заголовку только потому, что приложение находится за Nginx/Apache: сначала проверьте реальные `REMOTE_ADDR` и `HTTP_X_FORWARDED_FOR`. Плагин принимает цепочку только от адреса, входящего в allowlist, и ищет первый недоверенный адрес справа налево.
